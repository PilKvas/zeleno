# Feature Specification: Заметки для растений в саду

**Feature Branch**: `003-garden-plant-notes`

**Created**: 2026-09-11

**Status**: Draft

**Input**: User description: "Реализовать заметки для растений, добавленных в сад: на экране растения есть переход на список заметок с возможностью добавлять заметку."

## Clarifications

### Session 2026-09-11

- Q: Какой объём в первой итерации? → A: Список, создание, редактирование и удаление заметки.
- Q: Как выглядит переход к заметкам на экране растения? → A: Плитка «Заметки ›» на экране растения сада, после карточек ухода.
- Q: Где пользователь пишет заметку? → A: Отдельный экран формы; один экран для создания и редактирования.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Посмотреть и добавить заметку (Priority: P1)

Авторизованный пользователь открывает растение из «Моего сада», нажимает плитку «Заметки» и видит список своих заметок к этому растению (новые сверху). Нажимает «Добавить заметку», вводит заголовок и текст, сохраняет — возвращается в список, где появилась новая заметка.

**Why this priority**: Основная ценность — фиксировать наблюдения и действия по конкретному растению. Без списка и создания фича не существует.

**Independent Test**: На растении из сада открыть заметки, создать одну, убедиться, что она появилась в списке с заголовком, текстом и датой.

**Acceptance Scenarios**:

1. **Given** пользователь на экране растения из сада, **When** нажимает «Заметки», **Then** открывается список заметок этого растения.
2. **Given** заметок нет, **When** открывается список, **Then** видно пустое состояние и кнопка «Добавить заметку».
3. **Given** пользователь на форме заметки, **When** заполняет заголовок и текст и сохраняет, **Then** заметка создаётся, пользователь возвращается в список и видит её первой.
4. **Given** пользователь на форме заметки, **When** сохраняет с пустым заголовком или пустым текстом, **Then** заметка не создаётся и показывается сообщение о незаполненном поле.
5. **Given** пользователь на форме заметки, **When** заголовок длиннее 128 или текст длиннее 512 символов, **Then** заметка не создаётся и показывается сообщение о превышении лимита.
6. **Given** растение открыто из каталога (не из сада), **When** пользователь смотрит экран растения, **Then** плитка «Заметки» не показывается.

---

### User Story 2 - Отредактировать заметку (Priority: P2)

Пользователь нажимает на заметку в списке, видит форму с её заголовком и текстом, меняет их и сохраняет — список обновляется.

**Why this priority**: Заметки — живой дневник; исправление и дополнение записей нужно почти сразу после создания.

**Independent Test**: Открыть существующую заметку, изменить текст, сохранить, убедиться, что в списке новый текст.

**Acceptance Scenarios**:

1. **Given** в списке есть заметка, **When** пользователь нажимает на неё, **Then** открывается форма с предзаполненными заголовком и текстом.
2. **Given** пользователь изменил поля, **When** сохраняет, **Then** изменения сохраняются, пользователь возвращается в список и видит обновлённую заметку.
3. **Given** пользователь на форме редактирования, **When** нажимает назад без сохранения, **Then** изменения не применяются.

---

### User Story 3 - Удалить заметку (Priority: P3)

Пользователь на форме редактирования нажимает «Удалить заметку», подтверждает — заметка исчезает из списка.

**Why this priority**: Завершает CRUD; нужен реже создания и редактирования.

**Independent Test**: Удалить заметку с подтверждением и убедиться, что её нет в списке.

**Acceptance Scenarios**:

1. **Given** пользователь на форме редактирования, **When** нажимает «Удалить заметку», **Then** показывается подтверждение.
2. **Given** показано подтверждение, **When** пользователь подтверждает, **Then** заметка удаляется и пользователь возвращается в список без неё.
3. **Given** показано подтверждение, **When** пользователь отменяет, **Then** заметка остаётся, форма открыта.

---

### Edge Cases

- Ошибка сети при загрузке списка — показывается сообщение и кнопка «Повторить».
- Ошибка при сохранении/удалении — пользователь остаётся на форме, видит сообщение, введённые данные не теряются.
- Повторное быстрое нажатие «Сохранить» — запрос выполняется один раз.
- Растение удалено на другом устройстве — при действиях с заметками показывается ошибка «не найдено».
- Заголовок/текст из одних пробелов считаются пустыми.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: На экране растения из сада MUST быть переход к списку его заметок; для растения из каталога перехода нет.
- **FR-002**: Список MUST показывать заголовок, начало текста и дату обновления каждой заметки; порядок — по дате обновления, новые сверху.
- **FR-003**: Пользователь MUST иметь возможность создать заметку с заголовком (1–128 символов) и текстом (1–512 символов).
- **FR-004**: Пользователь MUST иметь возможность изменить заголовок и текст существующей заметки.
- **FR-005**: Пользователь MUST иметь возможность удалить заметку после подтверждения.
- **FR-006**: Система MUST валидировать поля до отправки и показывать понятные сообщения; пробелы по краям обрезаются.
- **FR-007**: После сохранения или удаления список MUST обновиться.
- **FR-008**: Ошибки загрузки и сохранения MUST показываться понятным текстом с возможностью повторить.

### Key Entities

- **Заметка растения**: принадлежит экземпляру растения в саду; заголовок, текст, дата создания, дата обновления.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Создание заметки — не более 3 экранов от карточки растения (карточка → список → форма).
- **SC-002**: Все сценарии US1–US3 проходят на dev-бэке без ручных обходов.
- **SC-003**: Юнит-тесты кубитов и репозитория покрывают валидацию, успех и ошибку каждого действия.

## Assumptions

- Бэкенд уже предоставляет CRUD заметок: `GET/POST /api/garden/plants/{plant_id}/notes`, `PATCH/DELETE /api/garden/plants/{plant_id}/notes/{note_id}`.
- Заметки доступны только авторизованному пользователю (растение из сада уже подразумевает авторизацию).
- Вложения (фото) в заметках — вне объёма v1.
- Заметка редактируется и удаляется с экрана формы; отдельного экрана просмотра нет.
